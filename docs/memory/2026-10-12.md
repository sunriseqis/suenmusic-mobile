## 一、冷启动根因：call 拉起不执行 onWindowStageCreate

官方 UIAbility 生命周期文档（uiability-lifecycle）明确：

- call（startAbilityByCall 语义）冷启动：**onCreate → onBackground**，
  **不执行 onWindowStageCreate**；
- 之后拉到前台才走：onNewWant → **onWindowStageCreate** → onForeground。

WebView 架构下页面加载挂在 windowStage 上 —— 后台冷启动窗口都没有，
Index/WebView 永远不加载，PlayerControlHub 的 pending 队列永远不放行。
指令其实到了（callee 正常收到），死在"没有网页可执行"。

**修法**（`EntryAbility.ets`）：`callee('control')` 里 dispatch 后检查
`isWebPageReady()`（PlayerControlHub 新导出），没就绪就
`this.context.startAbility({bundleName, abilityName: 自己})` 拉到前台，
按生命周期文档随后走 onWindowStageCreate → 页面加载 → onPageEnd →
`markWebPageReady()` 放行队列 → 播放。

⚠️ 待验证的平台限制：组件启动规则（component-startup-rules）说
「位于后台的 UIAbility 启动组件需校验 START_ABILITIES_FROM_BACKGROUND
（仅系统应用可申请）」。call 链起自用户点击卡片，模拟器是否豁免待实测；
被拒时降级（指令留队列 + 记日志），不影响其余功能。

## 二、封面：卡片 Image 加载不了网络 URL，走 formImages

官方机制（formBindingData d.ts + 卡片图片更新文档）：

1. 应用侧下载封面**原始字节**，落盘 `cacheDir/card_cover.img`
   （与 FormExtensionAbility 共享沙箱）；
2. 推送前开 fd，`{'formImages': {'suen_cover_img': fd}}` 随
   `createFormBindingData` 一起传；
3. 卡片侧 `Image('memory://suen_cover_img')` 显示。

限制：单图 ≤2MB（API19 前最多 5 张）。fd 生命周期：**updateForm 的
await 之后关闭安全**（IPC 已复制）；**onAddForm 的返回值参与序列化，
不能提前关**（泄漏的一个 fd 随 Extension 进程回收）。

实现（`Index.ets`）：`attachCover` 重构为一次下载两用 —— 字节写盘
（卡片）+ 解码 PixelMap（播控中心 mediaImage）；`syncCard` 按快照的
`coverReady` 开 fd 组装 formImages；`SuenFormAbility` 的 onAddForm /
onUpdateForm 同逻辑。

## 三、歌词按时间轴滚动

web 侧本来就每 ~1s 上报 positionMs（timeupdate 1 秒节流，第 47 条的
产物）。Harmony 侧把它写进快照（`positionMs` 字段），**只在活跃歌词行
变化时**才推卡片 —— 逐秒推既费 IPC 也不平滑。

- `NowPlaying.ets` 新增：`parseLyricLines`（容忍 [mm:ss] / [mm:ss.xx] /
  [mm:ss.xxx]，一行多标签展开）、`activeLyricIndex`、`buildLyricWindow`
  （当前行-1 起共 5 行）；
- payload 新增 `suen_lyric_active`（当前行在窗口内的下标），卡片背面
  ForEach 渲染窗口、活跃行加粗高亮；宽卡正面多一行"当前歌词"。

## 四、陈旧快照两处修

1. **播放键改发 `'toggle'`**：进程被杀后快照残留 `playing='true'` 时，
   按旧逻辑发 pause 是空操作、发 play 判错方向；toggle 两种情况都对。
   配套：Hub `VALID_CONTROLS` 加 'toggle'，web `registerGlobalAudioControl`
   加 `toggle`。
2. **`EntryAbility.onDestroy` 重置快照**：playing=false 落盘 + 推卡，
   全走同步 API（`writeSnapshotSync`，onDestroy 没有等异步 flush 的
   时间预算）。注意 onDestroy 只覆盖「最近任务划掉」，系统杀进程
   不保证回调。

## 八、模拟器实测反馈与第三轮修复（同日晚）

实测结果：② 封面 ✓、③ 歌词滚动 ✓、④ 深色 ✓；❶ **冷启动失败**；
另报：播放键永远显示 play 图标、全铺布局文字可读性差、两种规格大片空白。

### 8.1 冷启动：call 链不豁免，改 router 通道

实测日志（决定性证据）：

```
冷启动自拉前台被拒（code=201）：指令保留在队列，等下次进应用补执行。
The application does not have permission to call the interface.
```

即 `START_ABILITIES_FROM_BACKGROUND` 仅系统应用可申请，**call 链起自
用户点击也不豁免**（第 50 条的悬念落地）。startAbility 自拉前台此路不通。

最终修法：卡片按钮的 postCardAction 从 `call` 改 **`router`** —— 用户
点击卡片属于豁免通道，冷启动也把应用**完整**拉起（onCreate →
onWindowStageCreate → 页面加载），指令经 `want.parameters['control']`
交 Hub 排队（`dispatchControlFromWant` 已就绪）。代价：应用存活时按卡片
也会带到前台，WebView 架构下取舍后接受。EntryAbility 的 callee/call
路径保留但不再是主路。

### 8.2 播放键图标不刷新：@Builder 按值传参固化（文档明示的坑）

上一版把 `isPlaying() ? pause : play` 图标当参数传进 `@Builder ctrlBtn`。
ArkUI 文档明确：**@Builder 按值传参的 UI 不随状态刷新** —— 参数在首次
构建时被固化，`playing` 变了图标不动（红心同理）。修法：图标/颜色/尺寸
全部在 @Builder 体内经 `this.xxx`（@LocalStorageProp）计算。

### 8.3 布局 v3：全铺沉浸 → 封面块

用户反馈全铺封面文字可读性差、两种规格大片空白、歌词面利用率极低。
v3 废弃全铺 + 渐变遮罩，改「封面块 + 翻转区 + 控制排」共用骨架：

- **2\*2**：上 = 封面/歌词翻转区（layoutWeight 1 占满），下 = 标题/歌手
  + 控制排；
- **2\*4**：左 = 封面块（36%），右上 = 信息/歌词翻转区，右下 = 控制排；
- 文字全部落主题底色（可读性问题**结构性**消除，不再需要遮罩/毛玻璃）；
- 歌词面 5 行铺满整个翻转区，当前行 accent 高亮；
- 新增 `card_well` 色板（无封面占位底）：浅 `#DDE4EE` / 深 `#252B36`。

顺带查证：卡片白名单内可用的通用属性（d.ts 带 `@form` 标注）有
`blur` / `backdropBlur` / `backgroundBlurStyle` / `linearGradient` /
`shadow` —— 需要毛玻璃时有现成通路。

构建：HAP BUILD SUCCESSFUL。四项（router 冷启动 / 图标刷新 / 布局 v3 /
深色）待用户模拟器复验。结论沉淀进 `MEMORY.md` 第 51 条。

## 九、第四轮：v3 三连差评 → alive 分流 + 布局 v4（同日深夜）

v3 实测反馈三条：❶ router 通道"应用活着也拉前台"不合理；❷ 2*2 封面被
layoutWeight 条带裁切"非常难看"；❸ 翻转后维持原布局"非常非常难看"，
要求翻转=切换到全新布局（如封面沉浸）。

### 9.1 通道定稿：call/router 按 suen_alive 分流

矛盾：call 后台直达但冷启动是死路（50 条），router 冷启动可用但活着也
拉前台。解法是让卡片**知道应用死活**：

- 快照/payload 新增 `alive`：App 每次推卡必置 true；onDestroy 置 false；
- 卡片按钮分流：`alive==='true'` → call（后台直达）；否则 → router；
- 陈旧 alive（系统杀进程、onDestroy 不保证回调）：call 冷启动时
  EntryAbility 用 `justColdStarted` 标志（onCreate 置、onWindowStageCreate
  清）识别「WebView 未就绪 && 刚冷启动」→ **丢弃指令**（不排队——排了会
  和用户下一次 router 点击叠加成两次 toggle 抵消）→ 纠正 alive=false
  推回卡片 → 用户第二次点击走 router。第一次点击丢失是已知代价。

### 9.2 布局 v4

- **2\*2 正面**：回到封面全铺沉浸（封面大幅完整，不再条带裁切），
  底部 `backdropBlur(25)` + `rgba(12,16,24,0.38)` 毛玻璃圆角面板装
  标题/歌手/控制排 —— 可读性靠磨砂，不靠加深渐变。
- **2\*4 正面**：维持 v3（左封面块 36% + 右信息/控制）。
- **背面（两规格同构）**：点卡片翻转 = **整套布局切换**到「封面模糊
  沉浸」：封面全铺 `.blur(12)` + 深色渐变，标题/歌手在上、歌词窗口居中
  高亮、控制排在下。
- 调色板轴心 `onDarkOverlay()` = hasCover && (showBack || !isWide)：
  true 用固定深色令牌（歌词面/方卡正面），false 用主题资源令牌
  （宽卡正面/无封面态，自动深浅色）。

配套：NowPlaying 导出 `openCoverFd`/`closeCoverFd`（EntryAbility 纠正
alive 推卡时带封面 fd，防 formImages 缺失丢封面）；EntryAbility 的
`pushSnapshotToCards` 统一推卡路径；onDestroy 同时重置 playing+alive。

构建：HAP BUILD SUCCESSFUL。待用户复验：后台点卡片**不**拉前台（call）、
杀进程后第二次点击冷启动（router）、方卡沉浸观感、歌词面整套切换。
结论沉淀进 `MEMORY.md` 第 51/52 条。
