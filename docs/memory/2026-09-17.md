## 4. Android 永久官方签名体系与覆盖安装冲突彻底解决

### 问题现象
用户手机在每次安装新构建的 APK 时，即便版本号提升，依然提示“已安装相同签名的软件，无法直接覆盖”或“安装包签名冲突”。

### 根因定位
1. **GitHub Actions 临时 VM 每次随机生成 Keystore**：云端无持久证书时，Gradle 的 `assembleDebug` 会在临时机器的 `/root/.android/` 自动生成新的测试密钥对，导致每个构建的 APK 签名公钥互斥；
2. **Debug 调试包标记限制**：分发包为 Debug 包（`android:debuggable="true"`），国内各大品牌定制 ROM（小米 HyperOS、华为鸿蒙、OPPO、Vivo）的系统级安装器会拦截测试包对正式包的覆盖；
3. **版本号升级策略不连贯**：原版本号为 `-dev.<commit>`，手机端无法建立稳定的单调升级基线。

### 彻底根治措施
1. **内置永久统一正式签名库**：
   - 生成专用官方密钥库 `android/app/suenmusic.keystore`（RSA 2048 位，SHA-256 签名，有效至 2054 年），解除 `.gitignore` 限制并提交入库；
   - 在 `android/app/build.gradle` 中配置 `signingConfigs.release` 默认加载该密钥库，并开启 V1 + V2 签名机制。无论是云端 CI 还是开发者本地打包，签名永远 100% 相同。
2. **全面切换到 `assembleRelease`**：
   - 流水线直接编译正式版 Release 包，标记为生产包（`debuggable="false"`）；
   - 在 `build.gradle` 中增加 `lint { checkReleaseBuilds false; abortOnError false }`，跳过冗长的云端 LintVital 检查，打包速度提升数倍。
3. **确立 `v1.N` 正式版本体系**：
   - 项目根目录建立 `VERSION` 权威文件，当前版本为 `1.0`；
   - 内部 `versionCode` 采用 `10000 + 提交次数`（初始为 10088），单调递增且大于以往所有测试包；
   - 移除所有 Pre-release 逻辑，一律以正式版（`prerelease: false`）发布，命名规范为 `SuenMusic-v1.N.apk`；
   - 后续日常修复递增为 `1.1`、`1.2` 等，除非重大版本演进否则严格保持 `1.N`。
4. **历史脏 Tag 清理**：
   - 彻底删除远程所有 `v0.1.0-dev.*` 和临时 Tag，仅保留纯净的正式版本标签 `v1.0`。
